# 记忆系统使用规范

本项目配置了 memory-mcp-server 提供长期记忆能力。
MCP 工具名称为 `memory-*`，已在 `{{settings_path}}` 中注册。

## 热工作记忆（Hot Working Memory）

调用 `memory_search` 检索记忆后，**主动 Read `memory/work_memory.md`**：
- 该文件由 memory-mcp 后台持续维护：search 触发主体条目替换，后台定时轮询追加相关记忆
- 内容为「相关记忆的摘要 + 路径」，可直接消费摘要，深挖用 `memory_get_fragment(<fragment_id>)`
- 文件限大小（预算内），注满即停；新一轮 search 会替换主体条目
- 若你所在环境已通过 hook 自动注入本文件内容（如 Claude Code 的 UserPromptSubmit hook），直接消费注入内容即可，无需再主动 Read

## 回答前 → 查记忆

每次开始回答用户之前，先调用 `memory_search` 查询当前话题的相关记忆。
如果有命中，在回答中参考它们。

```
用法：搜索与当前讨论相关的历史记录
查询词：概括当前问题核心，比如"物理碰撞系统"、"受伤逻辑"、"动画状态机"
```

## 长期记忆检索规则（memory-mcp / P3 观察期）

调用 `memory_search` 检索长期记忆时，按下面走。目的是让「费劲且被采用」
的回忆留下干净信号，同时不给日常检索添摩擦。

### 何时用「完整 ReAct + 人工闸门」

只在**真拿不准**时用完整流程：一批检索结果里没有明显碾压项、或需要看逐字
原文才能定夺。反之，**rank-1 明显碾压、一击命中**时直接用那条，别念推理、
别问用户——摩擦只留给有价值的场景。

### 完整流程（拿不准时）

1. **念推理（Reason）**：看 `memory_search` 返回的一批摘要，用人话讲出你的
   判断——哪条像、哪条不像、为什么。**不要**把 cosine/similarity 分数摊给
   用户看；用户评的是你的语义判断，不是算法内部数值。
2. **换词再搜（Act）**：如果这批都不对，换个检索词再 `memory_search`。每次
   reformulate 都是一次有意义的「回忆成本」，别憋着一次问完，也别硬凑。
3. **问用户（人工闸门）**：锁定某一条、但拿不准时，先问
   「要不要我读一遍『XXX』这条的原文？」，等用户答复。
4. **点头后读原文**：用户说「读它 / 对 / 是」后，才调 `memory_get_fragment`，并带上：
   - `confirmed_by="user"` —— 经用户点头（金标准成功信号）
   - `query` —— 促成本次读取的检索词（助离线配对成回忆 episode）
   - `agent_id` —— 若在多 agent 场景

### confirmed_by 的语义（务必诚实标注）

- `confirmed_by="user"`：**用户明确点头**采用这条才填。这是唯一的金标准。
- `confirmed_by="agent"`：你**自行判定**要读、未经用户确认时填。
- 别把没问过用户的读取标成 `user`——观察期标歪只是噪声，但会污染
  Phase 1 的 go/no-go 判断。

### 每步念推理的意义

把推理说出来，用户能在**中途**就拦住走错的岔路，而不是等你选完才纠错。
